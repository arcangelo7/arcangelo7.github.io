### RAMOSE

Ho trovato un bug di performance. RAMOSE usava una sola sessione HTTP condivisa (requests.Session) e il valore predefinito della libreria teneva aperte solo dieci connessioni. Oltre quella soglia requests butta via la connessione TCP e ne crea una nuova. Ho sovrascritto con 100.

#### Benchmark

##### Esperimento 1

**Input**: un DOI
**Output**: OMID dell'opera richiesta, citazioni in entrata e metadati delle opere citanti
**Query remote**: una federazione su un singolo articolo
**Campionamento**: 100 DOI, 20 con 0 opere citanti, 20 con 1-9, 20 con 10-49, 20 con 50-99 e 20 con almeno 100
**Livelli di concorrenza**: 1, 4, 16
**Misurazioni**: 6.000 = 100 DOI \* 2 strategie \* 10 ripetizioni \* 3 livelli di concorrenza

Primi risultati, SERVICE è più veloce, con una leggera inversione oltre le 100 opere citanti. Ecco le mediane

| Opere citanti  | Concorrenza 1, SERVICE / orchestrazione | Concorrenza 4, SERVICE / orchestrazione | Concorrenza 16, SERVICE / orchestrazione |
| -------------- | --------------------------------------: | --------------------------------------: | ---------------------------------------: |
| Tutte le fasce |                          48,5 / 65,5 ms |                          59,1 / 80,9 ms |                         391,1 / 398,8 ms |
| 0              |                          48,5 / 52,8 ms |                          51,8 / 55,9 ms |                         184,5 / 234,8 ms |
| 1-9            |                          52,4 / 57,6 ms |                          55,0 / 63,3 ms |                         254,3 / 293,9 ms |
| 10-49          |                          26,2 / 69,0 ms |                          41,9 / 77,1 ms |                         327,3 / 355,6 ms |
| 50-99          |                          47,0 / 86,9 ms |                         67,0 / 101,3 ms |                         492,7 / 501,7 ms |
| 100+           |                        148,0 / 149,2 ms |                        210,5 / 202,0 ms |                   1.072,9 / **970,6 ms** |

E qui interviene la sofisticata arte del benchmarkmaxxing. <Image src={uhyngt} alt="" width="170" height="auto" /><Image src={hygfix} alt="" width="170" height="auto" /><Image src={remjli} alt="" width="170" height="auto" /><Image src={pvlhsm} alt="" width="171" height="auto" />

Stiamo mettendo sotto stress il SERVICE? Manco penniente.

Ci sono delle operazioni sulle API di OC che metterebbero sotto sforzo il SERVICE? Sì: quelle che chiedono più entità alla volta, perché il numero di chiamate al server federato aumentano.

Ok, e volendo essere ancora più stronzi? Si potrebbe fare una cosa tipo /venue-citation-count. Si parte da un ISSN, si trovano tutti gli articoli associati e per ciascuno si federa a Index
